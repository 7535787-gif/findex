# План 5-хвилинного захисту Lab 08

1. **0:00–0:40 — Демонстрація.** Відкрити вебінтерфейс, виконати один keyword-запит,
   перемкнути режим на semantic або hybrid (після налаштування embeddings).
2. **0:40–1:40 — Профілювання.** Показати три гарячі точки: `build_partial`,
   `tokenize`/Unicode normalization та `make_snippet`/regex. Пояснити різницю
   між Python і native time. Чесно зазначити, що py-spy sampling SVG не вдалося
   отримати у Windows через помилку визначення версії Python.
3. **1:40–2:40 — NumPy.** Показати `int32` postings, векторизовані BM25/TF-IDF,
   `argpartition` і тест, який порівнює порядок та оцінки з Lab 3.
4. **2:40–3:40 — Вимірювання.** Навести три запити з `numpy-benchmark.md` та
   синтетичний тест 10 000 документів. Пояснити, чому NumPy не прискорює
   короткі списки postings, але виграє на довгих.
5. **3:40–4:30 — Семантичний пошук.** Показати `findex embed`, semantic mode,
   hybrid mode та RRF; навести фактичну таблицю Precision@5 після запуску
   evaluation script.
6. **4:30–5:00 — Висновок і урок.** Найкраще вимірювання — прискорення на
   довгих postings; важливий урок — оптимізацію треба починати з профілювання,
   а не з припущень.

Перед захистом замінити цей план конкретними скриншотами/демонстрацією та
додати фактичну таблицю 15 запитів після запуску semantic evaluation.
